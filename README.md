# 부스럭 (moong-techtoon) 프론트엔드

축제 주최자가 행사 지도를 만들고 부스 신청을 관리하며, 부스 운영자가 신청·참여하는 서비스의
프론트엔드입니다. React + Vite로 만들었고, **주최자 화면은 백엔드(`backend-main`)와 연결**되어 있습니다.

> 연결 방식·API 대응표·남은 일은 [BACKEND_INTEGRATION.md](BACKEND_INTEGRATION.md)를 참고하세요.
> 부스 운영자·방문객 쪽 화면(운영자 신청·초대 수락·부스 직접 운영 등)은 아직 만들지 않았습니다.

## 실행 방법

백엔드와 프론트를 같이 쓰려면 터미널 2개가 필요합니다.

```powershell
# 터미널 1 — 백엔드 (backend-main 폴더, Docker Desktop 실행 후, JDK 21 필요)
docker compose up -d --wait db
.\gradlew.bat bootRun

# 터미널 2 — 프론트 (이 폴더)
npm install      # 처음 한 번
npm run dev      # 개발 서버 (http://localhost:5173)
```

프론트 개발 서버가 `/api` 요청을 `http://127.0.0.1:8080`(백엔드)으로 전달합니다.

```bash
npm run build    # 배포용 빌드 (dist/)
npm run preview  # 빌드 결과 미리보기
npm run lint     # 코드 검사
```

## 화면 / 경로

| 경로 | 화면 |
|---|---|
| `/` | 랜딩 (컴퓨터·노트북 1024px 이상: 서비스 소개 페이지 / 그보다 좁으면 휴대폰용 카드) |
| `/login` | 로그인 |
| `/signup` | 로그인 + 회원가입 유형 선택 |
| `/signup/organizer` | 축제 주최자 회원가입 |
| `/signup/booth` | 부스 운영자 회원가입 |
| `/home` | 메인 (준비 중) |
| `/organizer/dashboard` | 주최자 · 대시보드 (로그인 필요) |
| `/organizer/map` | 주최자 · 지도 제작 |
| `/organizer/recruit` | 주최자 · 부스 모집 |
| `/organizer/live` | 주최자 · 실시간 운영 현황 |
| `/organizer/booths` | 주최자 · 부스 관리 |
| `/organizer/notices` | 주최자 · 공지사항 |

### 랜딩 (`/`, 1024px 이상)
- 서비스 소개 + **행사 개설 신청하기** 버튼(지금은 주최자 회원가입으로 이동). 오른쪽 운영 화면 미리보기가 대시보드 → 지도 제작 →
  부스 관리 → 운영 현황 → 공지사항 순으로 4초마다 바뀌고(앞 화면은 흐려지고 다음 화면이 선명해짐), 점을 눌러 직접 고를 수 있음
- 마우스를 올리면 멈추고, "동작 줄이기" 설정을 켠 사용자에게는 자동으로 바뀌지 않음

### 로그인 · 행사 개설
- 회원가입(주최자/부스 운영자): 아이디 중복 확인, 입력 검증, 가입 후 로그인 화면으로 이동
- 로그인 / 로그아웃: 상단 바의 닉네임을 눌러 로그아웃. 새로고침해도 로그인 유지
- `/organizer/*` 화면은 로그인해야 열림 (아니면 `/login`으로 이동했다가 로그인 후 원래 페이지로 복귀)
- **행사는 사용자가 직접 만들지 않습니다.** 랜딩의 "행사 개설 신청"을 관리자가 승인하면 행사가 열립니다. 행사가 없는 주최자는
  신청한 적이 없으면 신청서, 검토 중이면 대기 화면, 반려됐으면 사유가 적힌 신청서를 봅니다. 승인되면 같은 계정으로 바로
  대시보드를 쓸 수 있습니다. 관리자는 `/admin/applications`에서 신청을 검토합니다(관리자 계정은 DB에서 지정, BACKEND_INTEGRATION.md 8장).
- 행사가 여러 개인 계정은 가장 최근에 만든 행사를 씁니다 (행사 선택 화면은 아직 없음).
- 부스 운영자 계정은 행사가 없으면 **"부스 운영자 전용 화면은 준비 중" 안내**가 나옵니다. 백엔드가 가입 유형을 저장하지 않아서, 이 브라우저에서 가입한 운영자는 기록해 두었다가 알아보고, 그 외에는 부스 신청·부스가 있는 계정을 운영자로 봅니다.

### 대시보드 (`/organizer/dashboard`)
- 행사 정보, 부스 모집 현황, 부스 운영 요약(전체 부스 · 운영 중 · 준비 중 · 품절 · 마감)
- **행사 정보 수정**: 이미지·이름·날짜·장소·소개를 저장하면 사이드바 카드 등 모든 화면에 바로 반영
  (행사 이미지는 바꿀 수는 있지만 지울 수는 없음 — 백엔드에 삭제가 없음)
- 행사 진행 상태는 날짜로 자동 표시: 시작 전 **진행 예정**, 기간 중 **진행 중**, 끝난 뒤 **진행 종료**
- 최근 공지사항(게시된 것 최대 3개), 방문객 링크·QR(임시 그림)
- **부스 운영자 초대**: 초대 코드·링크를 발급 / 다시 발급 / 종료. 코드는 **발급한 직후에만** 볼 수 있어서(서버는
  해시만 저장) 그때 복사해 두어야 함. 모집 공고를 공개하고 마감일을 저장해야 발급 가능

### 실시간 운영 현황 (`/organizer/live`)
- 승인된 부스 + 직접 등록한 부스 표시: 전체 · 준비 중 · 운영 중 · 품절 · 마감 수는 서버가 세어 줌
- 부스 목록: 이름 검색, 운영 상태 · 재고 현황 · 배치 필터(모두 서버에서 처리), 페이지 이동. **운영 상태 버튼을
  눌러 바로 변경**
- 부스 상세: 메뉴 추가·삭제, 메뉴별 재고(무제한/충분/부족/품절)를 눌러 변경, **방문객 공개 여부** 변경, 최근 변경 시각, 부스 소개
- 부스 위치는 **게시된 지도**의 핀 기준. "지도에서 크게 보기"는 방문객에게 보이는 지도(공개 부스만)를 보여 주고,
  게시된 지도가 없으면 그 부스의 핀만 보여 줌
- 5초마다 자동 갱신(탭이 숨겨져 있으면 멈춤) / 새로고침

### 부스 모집 (`/organizer/recruit`)
- 모집 공고 작성: 소개글, 대표 이미지(=행사 대표 이미지), 모집 마감일, 모집 부스 수, 모집 카테고리, 참가비(금액 + 안내),
  필요 서류(직접 추가·삭제 가능)
- **저장하기**를 눌러야 반영되고, 저장하지 않은 변경이 있으면 표시됨. **미리보기**로 운영자에게 보일 공고 확인
- 모집 상태는 자동: 공개 중 + 마감 전이면 **모집 중**, 마감일이 지나면 **모집 마감**, 공개를 끄면 **비공개**
  (공개 종료는 확인 창). **공개하기**를 누르면 행사도 함께 공개돼요(공개 모집 페이지가 공개 행사에만 있음)
- 첫 신청이 들어온 뒤에는 카테고리·참가비·필요 서류를 바꿀 수 없음(백엔드 규칙)
- 신청 현황(접수·검토 중·승인·반려)은 서버가 세어 주고 부스 관리·대시보드와 같은 값

### 지도 제작 (`/organizer/map`)
- 평면도(PNG/JPG, 10MB 이하) 업로드 → **편집 중인 초안**이 만들어짐. 삭제하면 초안과 핀이 모두 삭제됨
- 핀 종류(부스·화장실·안내소·의무실·기타 시설)를 골라 지도를 클릭하면 핀이 찍힘, 드래그 이동, 좌표 입력, 삭제
- 승인했거나 직접 등록한 부스를 선택한 핀에 할당 (부스 핀의 라벨은 부스 번호)
- 부스가 할당되지 않은 부스 핀이나 방문객에게 비공개인 부스의 핀은 게시해도 방문객 지도에 나오지 않으므로, 지도 제작 화면과 게시 확인 창에 경고가 뜹니다
- **저장하기**는 초안만 저장하고, **게시하기**를 눌러야 방문객에게 보임(이전 게시본은 보관됨).
  게시된 지도만 있을 때는 "게시된 지도로 수정 시작"으로 복사본에서 이어서 수정

### 부스 관리 (`/organizer/booths`)
- 신청 목록(서버 검색·필터·정렬·페이지): 부스명 검색, 카테고리·상태 필터, 최신/오래된순
- 신청 상세: 신청 정보, 제출 서류 상태, 검토 메모(칸을 벗어날 때 저장), 반려 사유
- 서류는 서비스 밖에서 받으므로 **상태만 기록**(미제출/제출됨/확인 완료/보완 필요). 필수 서류가 모두 "확인 완료"여야 승인됨
- 승인하기 / 반려하기(반려 사유 필요): **한 번 정하면 되돌릴 수 없음**(확인 창). 승인하면 부스 번호(B001…)가 자동으로 부여됨
- **+ 부스 직접 등록**: 신청 없이 부스를 만듦 (신청 목록에는 나타나지 않고 운영 현황·지도에 나타남)
- **초대 링크 복사**: 이 화면에서 방금 발급한 링크가 없으면 새로 발급(이전 링크는 못 쓰게 됨)

### 공지사항 (`/organizer/notices`)
- 왼쪽 공지 목록: 제목 검색, 대상 필터, 게시 상태 표시, 긴급 공지는 목록 맨 위
- 오른쪽에서 먼저 **열람**하고, `수정하기` 버튼을 눌러야 수정 화면으로 전환
- 새 공지 작성: 제목 · 본문 · **이미지 1장(PNG/JPG, 10MB 이하)** · 공지 대상 · 긴급 공지
- 임시 저장 / 게시하기 / 수정 저장 / 게시 종료 / 다시 게시 / 삭제(확인 창)
- "게시 종료"는 백엔드에서 임시 저장 상태로 되돌리는 것이고, 한 번 게시한 적이 있으면 목록에 "게시 종료"로 표시됨

## 폴더 구조

```
src/
├─ pages/        화면 (랜딩, 로그인, 회원가입, 행사 대기·운영자 안내, 대시보드, 지도 제작, 부스 관리, 부스 모집, 실시간 운영 현황, 공지사항)
├─ components/   공통 컴포넌트 (OrganizerLayout, RequireAuth, RequireEvent, Toast 등)
├─ constants/    상태·카테고리·핀 종류 코드(백엔드와 같은 값)와 한글 라벨, 오류 문구
├─ api/          백엔드 호출 (client, authApi, eventApi, recruitApi, boothApi, noticeApi, mapApi)
├─ context/      로그인·행사·초대·모집·부스 집계·공지·지도 저장소 (…Provider) 와 useEventData
├─ utils/        날짜·행사·모집·공지 변환 함수, useToast
├─ assets/       이미지, 핀 아이콘
├─ types.js      Event, Recruitment, Notice, Pin, Floorplan 등 모델 정의
└─ App.jsx       라우팅 · Provider 순서
```

## 참고
- 화면 레이아웃은 데스크톱(가로 1081px 이상)에서 한 화면에 맞도록 만들어져 있고, 휴대폰 규격은
  별도로 맞추지 않았습니다.
- 백엔드 업무 API는 `local` 프로필에서만 열려 있습니다(`deploy` 프로필에는 없음).
