# 백엔드에 요청할 것 (누구나 이해할 수 있게)

프론트를 만들면서 "서버에 없어서 임시로 브라우저에 저장해 둔 것 / 화면에 자리만 만든 것"을 모았습니다.
각 항목: **왜 필요한지 → 무엇을 만들어 달라는 건지 → 지금 프론트는 어떻게 하고 있는지**.
(작업하면서 계속 추가됩니다. 🔴 = 이거 없으면 막힘 / 🟡 = 있으면 화면이 와이어프레임대로 완성됨 / 🟢 = 나중에 해도 됨)

---

## 🔴 1. 새 주최자가 행사를 만들 수 없음
- 왜: 행사는 "단체(조직)"가 있어야 만들 수 있는데, 가입하면 단체가 안 생기고 단체를 만드는 API도 배포본에 없습니다. 그래서 새 주최자는 대시보드를 쓸 수 없습니다.
- 요청: 행사 개설 신청서(단체 이름, 행사 이름·기간·장소 등)를 받으면 **단체와 행사를 한 번에 만들어 주는 API** 1개. 승인 절차는 나중에 추가해도 됩니다.
- 참고: backend 저장소 main(97cb075)에 이미 구현해 둔 코드가 있습니다(승인 단계 포함).
- 프론트: 지금은 신청서를 브라우저에만 저장하고, 제출하면 바로 승인된 것처럼 임시 행사로 대시보드를 보여줍니다(`src/api/eventApplicationApi.js`). 서버 행사가 없어서 모집·부스·지도·공지 같은 기능은 저장이 안 됩니다.

## 🔴 2. 계정의 역할(주최자 / 부스 운영자 / 스태프)을 서버가 저장해야 함
- 왜: 로그인하면 역할에 따라 다른 화면(주최자 대시보드 / 운영자 앱 / 스태프 앱)으로 보내야 하는데, 서버가 가입 유형을 저장하지 않고 `/api/me`도 알려주지 않습니다. 스태프 가입 유형도 서버가 모릅니다(`onboardingType`은 ORGANIZER·OPERATOR만 받음).
- 요청: ① 가입 유형에 `STAFF` 추가 ② 가입 유형을 계정에 저장 ③ `/api/me` 응답에 `role`(ORGANIZER / OPERATOR / STAFF) 포함.
- 프론트: 지금은 가입한 브라우저에만 역할을 기억하고(`src/utils/role.js`), 스태프는 OPERATOR로 가입시킨 뒤 STAFF로 기억합니다. 그래서 다른 기기/브라우저로 로그인하면 역할을 모릅니다.

## 🟡 3. 행사에 "운영 시간 · 오시는 길 · 문의처(운영본부 전화)" 필드
- 왜: 방문객 홈("오늘 운영 11:00 - 21:00"), 행사 정보(오시는 길, 문의처), "운영본부 연락" 버튼에 쓰입니다.
- 요청: 행사 정보 API(조회·수정)에 `operatingHours`(시작/종료 시각), `directions`(오시는 길 안내 글), `contactPhone` 추가. 공개 조회(`/api/public/events/{id}`)에도 포함.
- 프론트: 값이 없으면 해당 줄을 숨기고, 연락 버튼은 "연락처가 아직 등록되지 않았어요"라고 안내합니다.

## 🟡 4. 부스에 "사진 · 운영 시간 · SNS 링크"
- 왜: 방문객 부스 목록/상세 카드의 사진, 상세의 운영 시간·"부스 SNS 보기", 운영자의 "내 부스 정보 수정"(사진·운영 시간)에 쓰입니다.
- 요청: 부스 수정 API에 `operatingHours`, `snsUrl`, 사진(기존 이미지 업로드 API 재사용: `mediaAssetId`) 추가. 공개 부스 목록/상세 응답에 `imageUrl`, `operatingHours`, `snsUrl` 포함.
- 프론트: 사진 대신 기본 아이콘 칸, 운영 시간은 운영자가 입력해도 그 브라우저에만 저장(`getBoothHours`), SNS는 값이 없으면 숨김.

## 🟡 5. 후원사(스폰서) 와 홈 광고 배너
- 왜: 방문객 홈의 광고 카드·"함께하는 파트너", 행사 정보의 "함께하는 파트너" 전체 목록(메인/일반 구분, 웹사이트 링크). 통계 화면의 "후원사 성과"(노출 수·클릭 수)에도 이어집니다.
- 요청: 주최자가 후원사를 등록·수정·삭제하는 API(이름, 메인 여부, 한 줄 소개, 웹사이트 URL, 로고 이미지, 광고 문구)와 방문객용 공개 조회 `GET /api/public/events/{id}/sponsors`. 노출·클릭 기록 API(통계용).
- 프론트: 서버에 없으니 일반 모드에서는 이 영역을 숨기고, `?demo=1` 미리보기에서만 샘플을 보여줍니다.

## 🟡 6. 부스 신청서의 추가 항목 (판매 품목 · 필요 설비 · 주최측 추가 질문 · 서류 업로드)
- 왜: 와이어프레임 신청서에는 판매 품목, 필요 설비(전기·물·화기·테이블), 주최측이 정한 질문, 서류 파일 업로드가 있는데, 신청 API(`POST /events/{id}/applications`)는 부스 프로필 ID와 연락처만 받습니다.
- 요청: ① 신청에 `salesItems`, `equipment[]`, `answers[]` 저장 ② 주최자가 모집 공고에서 "추가 질문"을 정할 수 있게(질문 문구·선택지) ③ 서류 파일 업로드(기존 서류 요건 `documentRequirements`와 연결) 및 부스 관리 화면에서 열람.
- 프론트: 입력 칸은 만들어 두었고 서버에는 보내지 않습니다(화면에 "아직 서버에 저장되지 않아요" 안내).

## 🟡 7. 결제 내역(입점비·수수료)
- 왜: 운영자 프로필의 "결제 내역"(행사명, 금액, 결제 완료 여부).
- 요청: 운영자별 결제 목록 조회 API `GET /api/me/payments`(행사, 항목, 금액, 상태, 일시). (결제 처리 자체는 범위 밖이면 목록만)
- 프론트: 일반 모드에서는 숨기고 미리보기에서만 샘플 표시.

## 🟡 8. 계정 정보 수정 · 비밀번호 변경
- 왜: 운영자/스태프 프로필의 "계정 정보 수정"(이름, 연락처, 이메일, 비밀번호).
- 요청: `PATCH /api/me`(닉네임·연락처·이메일), 비밀번호 변경 API.
- 프론트: 지금은 읽기 전용 화면과 "준비 중" 안내만 있습니다.

## 🟢 9. 재고 단계 "중간" · 공지 분류와 첨부파일
- 재고: 와이어프레임은 충분/중간/부족/품절 4단계인데 서버는 충분(AVAILABLE)/부족(LOW)/품절(SOLD_OUT)/무제한(UNLIMITED). 4단계가 필요하면 `MEDIUM` 추가 요청, 아니면 프론트를 서버 값에 맞춤(현재 이렇게 함).
- 공지: 와이어프레임 목록에 "긴급/운영/안내" 같은 분류와 PDF 첨부가 보입니다. 서버는 긴급 여부와 이미지 1장만 있습니다. 분류(category)와 파일 첨부가 필요하면 추가 요청.

## 🔴 10. 스태프 기능 전체 (지금은 서버에 아무것도 없어서 브라우저에 임시 저장)
스태프는 "행사 운영을 도와주는 사람"입니다. 주최자의 **스태프 화면(명단·근무표·실시간 현황)** 과 스태프 본인의 **모바일 앱(초대 코드 입력 → 승인 대기 → 홈·일정·공지·프로필)** 이 같은 데이터를 봅니다.

필요한 데이터(표 하나씩 생각하면 됩니다):
| 무엇 | 담아야 할 것 |
|---|---|
| 스태프 초대 | 행사별 초대 코드(예: BL26-STF7)와 초대 링크 토큰, 만료·폐기 |
| 스태프 참여 신청/멤버 | 계정, 행사, 역할(스태프·관리자·근로·봉사), 상태(승인 대기·대기 중·근무 중·휴식 중·미출근·거부), 소속, 주최측 참고 메모 |
| 업무(duty) | 행사별 "구역 + 업무 이름"(예: 정문 / 입구 안내) |
| 근무표(shift) | 날짜, 업무, 시작·종료 시각, 허용 역할, 배정된 멤버 목록 |
| 출퇴근 기록 | 멤버, 날짜, 출근 시각, 퇴근 시각 |

필요한 API(제안):
- 주최자: 초대 코드 발급/폐기, 멤버 목록·상세·역할/업무/상태 변경·승인/거부·메모, 업무 추가, 근무표 조회·추가·배정 저장, 실시간 현황(업무별 근무 중 인원, 미배정 인원)
- 스태프 본인: 초대 코드(또는 링크)로 행사 확인 → 역할 선택해 참여 신청, 내 신청 상태, 내 일정(날짜별 + 함께 근무하는 사람), 출근/퇴근 기록, 내 근무 기록, 내 정보 수정, 스태프용 공지 조회
- 이 모든 것의 권한: 스태프는 자기 행사 데이터만, 주최자는 자기 행사 전체

프론트: 같은 모양의 데이터를 `src/dummy/staffStore.js`(브라우저 저장)에 두고 화면을 모두 만들어 두었습니다. API가 생기면 이 파일의 함수 본문을 서버 호출로 바꾸면 됩니다. 스태프 초대 코드는 지금 `BL26-STF7`만 통과하는 가짜입니다(`src/api/staffApi.js`).

## 🟡 11. 통계 (조회 수 · 후원사 광고 성과)
- 왜: 주최자 통계 화면(웹 조회 수, 부스 상세 조회 수, 광고 노출·클릭 수, 시간대별 웹 조회 그래프, 부스 상세 조회 TOP 5, 후원사별 노출·클릭·클릭률, 엑셀 다운로드).
- 요청: ① 방문객 앱에서 보내는 **이벤트 기록 API**(화면 조회, 부스 상세 조회, 광고 노출, 광고 클릭 — 행사·시각·대상 포함, 로그인 불필요) ② 주최자용 **집계 API**(기간 선택 가능: 합계, 시간대별, 부스별 TOP N, 후원사별) ③ 엑셀(CSV) 내려받기는 프론트에서 화면 숫자로 만들 수 있어 서버 작업 불필요.
- 프론트: 화면에 "예시 데이터" 표시를 달고 `src/dummy/statsData.js`의 가짜 숫자를 보여줍니다.

## 🟢 12. 알림(종 모양 아이콘)
- 왜: 모든 앱 상단의 종 아이콘. 지금은 공지 목록으로 이동만 합니다.
- 요청(나중에): 새 공지·승인 결과 등을 알려 주는 알림 목록/읽음 처리 API.

## 프론트에서 화면을 먼저 확인하는 방법 (백엔드 담당자용)
`npm run dev` 후 주소 끝에 `?demo=1`(참여한 계정) 또는 `?demo=2`(새 계정)을 붙이면 서버 없이 샘플 데이터로 모든 화면을 볼 수 있습니다.
방문객 `/e/demo-event`, 부스 운영자 `/operator/home`, 스태프 `/staff/home`, 주최자 `/organizer/staff`·`/organizer/stats`. (`?demo=0`으로 끄기)
